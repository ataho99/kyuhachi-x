# 큐하치 X 헤드리스 키 주입 — 뮤즈 지시서에 붙일 문서 (t831 소스 기준, 2026-11-17)

근거 표시: [소스] = 소스 읽고 확인 · [실사용] = 이미 돌아간 스크립트(꽃의기억 hana_t816v_v1d.sh 등)가 같은 방식 · [미확인] = 아직 안 돌려 봄.

## 1. 실행 폴더 (작업 사본)  [실사용]
원본 게임 폴더·라이브 폴더에서 직접 돌리지 않는다. 작업 사본 폴더 `R` 하나를 만들어 거기서 돌린다.
- 넣을 것: `KyuhachiX.exe`, `res\`, `settings.ini`, `strings_ko/en/ja.txt`, `gamedb.ini`, `gamedb_nk*.tsv`, `games\<id>\game.ini` (참고: work\20261116_꽃의기억\hana_run.sh 의 복사·game.ini 작성부)
- game.ini 예(CD 없는 HDI 부팅): `[game]` `id=<id>` `title=…` `lang=ko` `imgdir=<이미지 폴더(Windows 경로)>` `disk_a=…hdm` `disk_c=…hdi` `boot=A` `[override]`. CD 가 있으면 `cd=….ccd` 한 줄 추가.
- 같은 `R` 에서 두 번 동시에 돌리지 않는다(logs 충돌). 병렬이면 `R` 을 복사해 따로 쓴다.

## 2. 한 번 실행  [소스·실사용]
```
cd R
timeout $((SEC+60)) ./KyuhachiX.exe --headless --sec SEC --shot 8,16,24 --inject 대본.txt <id> > out.txt 2>&1
```
- `--headless` 창·소리 장치 없음(소리는 dummy 드라이버). 화면은 메모리에서만 그려짐.
- `--sec N` 게임 시작(부팅 끝) 뒤 N 초에 정상 종료. `timeout` 은 안전망(종료 못 하면 강제).
- `--shot a,b,c` 게임 시작 뒤 그 초(소수 가능)에 스크린샷 → `R\logs\<id>\shot_*.png` (640×400, 오버레이·메뉴 없는 에뮬 화면).
- `--inject 파일` 입력 대본(아래 3). 대본 없이도 돈다.
- 로그: `R\logs\<id>\kyuhachi_log.txt` (`INJECT t=…` 줄로 실제로 먹은 입력 확인, `OUTRMS`/`RMS window` = 소리 크기).
- 시간 단위: 대본의 ms 와 `--sec`/`--shot` 의 초는 모두 「게임 시작(since) 기준」. 부팅·로딩 시간은 포함되지 않음 → 같은 대본이면 같은 시각에 같은 입력이 들어감.

## 3. 입력 대본 형식  [소스]
한 줄 = `<ms> <명령> [인자]`, `#` 줄·빈 줄 무시, ms 오름차순.
| 명령 | 뜻 |
|---|---|
| `key <SDL키이름> 1` / `key <SDL키이름> 0` | 키 누름 / 뗌 (창 포커스 불필요). 이름 예: `Return` `Space` `Escape` `Up` `Down` `Left` `Right` `Z` `X` `A`…`Z` `1`…`0` `F1`.. |
| `tap <패드버튼>` | 패드 버튼 누르고 120 ms 뒤 뗌. 이름: `a b x y start back leftshoulder rightshoulder dpup dpdown dpleft dpright` |
| `cbtn <패드버튼> 1/0` | 패드 버튼 누름/뗌 직접 |
| `log <글>` | 로그에 표식 한 줄 (장면 구분용) |
- 키는 항상 누름·뗌 쌍. 뗌은 누름 + 100~150 ms. 같은 키 연타는 간격 1000 ms 이상 권장(게임이 입력을 놓침).
- 예(Return 연타로 메시지 넘기기, hana_t816v 와 같은 형태):
```
9000 key Return 1
9150 key Return 0
10400 key Return 1
10550 key Return 0
```
- 키가 PC-98 쪽에서 어떤 키가 되는지는 기존 키 매핑을 따름 — Return=RETURN, Space=SPACE, 방향키=방향키 [미확인: 게임별 Z/X 가 결정/취소인지는 화면으로 확인].

## 4. 화면·소리 판정 (사람 눈 없이)  [실사용 + 새 기능]
- 장면 전환 감지: 스크린샷 PNG 를 `md5sum` 으로 비교(같으면 화면 정지, 다르면 변화).
- 소리가 났는지: 로그 `OUTRMS`(전체 출력 rms) 또는 아래 5 의 장치별 WAV 요약(`summary.tsv` 의 rms/dBFS).
- 조작이 먹었는지: 로그에 `INJECT t=<ms> key Return 1` 이 찍혔는지 + 직전·직후 스크린샷 md5 가 다른지.

## 5. 장치별 파형 덤프 (t832 소스에 추가, 아직 미빌드)  [소스]
추가 인자(헤드리스·창·안드로이드 모두): `--wavdump <폴더>` `[--wavsolo fm,ssg,rhythm,adpcm,pcm86,beep,cdda,sb]` `[--wavfrom 초]`
- 믹서 채널마다 WAV 하나(볼륨 곱 전, 믹서 출력 주파수, 스테레오 16비트). 채널: `PC-98`(FM·SSG·리듬·ADPCM·PCM86 합), `SPKR`(비퍼), `CDAUDIO`(CD-DA), `SB`/`PCM`(SB 계열).
- 부품별은 `--wavsolo` 로 하나씩 켜서 여러 번(같은 대본으로) 돌린다 → `tools\wavdump_run.sh <R> <id> <초> <대본|-> <출력폴더>` 가 전부 돌리고 `all_summary.tsv`(태그·채널·peak·rms·dBFS)를 만든다.
- 끝나면 `<태그>_summary.tsv` 와 로그 `WAVDUMP …` 줄. 어느 부품/채널에서 소리가 나왔는지는 rms 가 0 이 아닌 쪽 — 그 자체가 「장치 판별」.
- 덤프 중에는 슬라이더 설정이 무시되고 볼륨이 고정된다(전부 1.0, solo 에 없는 부품 0).
- 대본이 같아도 에뮬 타이밍은 실행마다 조금 다를 수 있음 → 부품 간은 「소리 난 구간 rms 크기」로 비교, 샘플 정렬은 기대하지 않음.
