# 치트 설계 v1 (kx-cheat) — 2026-11-13

슨상 결정(2026-11-13 03:40): 「좋은데?」 / (03:41): 「굉장히 원시적이면 될거 같긴한데 예전 cheat-o-matic처럼」

## 원칙
- 굉장히 원시적으로: 화면에 보이는 숫자를 넣어 찾고, 값이 바뀌면 다시 찾고, 후보가 적어지면 쓴다. 「늘었나/줄었나/그대로」 비교 검색은 없다.
- 패드만으로 된다(숫자 칸 + ○). 터치는 목록 줄 탭까지(기존 목록 위젯 그대로).
- 치트 파일이 없어도 게임은 그대로 돈다. 치트 쓰기 전에는 기존 자동 슬롯(auto)에 먼저 저장한다(새 슬롯 없음).
- 사용자 세이브·상태 파일은 건드리지 않는다.

## 1단계 (구현됨, 미빌드)
화면: 일시정지 메뉴(이어하기·저장·불러오기·디스크교체·설정·키보드) 다음에 「치트」 줄 추가. 안에는 한 화면에 여섯 줄.

| 줄 | 동작 |
|---|---|
| 값: N | 숫자 칸(1~9·<·0·OK)이 열린다. ○ 입력, □ 지움, SEL 완료 |
| 찾기 / 다시 찾기 | 처음엔 RAM(0~9FFFF) 전체에서 N 을 8·16·32비트 동시에 찾는다(사용자는 크기를 고르지 않음). 값 크기에 안 맞는 폭(예: 1234 는 8비트 불가)은 자동 제외. 다시 찾기는 이전 후보 안에서 현재 값이 새 N 인 것만 남긴다 |
| 후보 보기 | 후보가 많으면 개수만, 8개 이하일 땐 목록(주소·폭·현재값). 하나 고르고 쓸 값을 입력 → 쓰기(한 번) / 고정(매 프레임 다시 씀) / 저장(고정·한 번) |
| 처음부터 | 후보·입력 값 비움(버튼 하나) |
| 저장된 치트 | 이 작품 JSON 의 치트 목록. ○ 적용, △ 삭제 |
| 고정 모두 풀기 | 걸린 고정 해제 |

후보 개수는 항상 표시. 후보가 5만 개를 넘으면 앞 5만 개만 들고 「너무 많아 일부만」 표시(값을 바꿔 다시 찾으면 줄어든다).

### 저장 형식
- 위치: 안드로이드 `/sdcard/Kyuhachi/cheats/<작품ID>.json`, 윈도 실행 폴더 `cheats\<작품ID>.json`. 사람이 읽는 JSON.
- 항목: name, width, value, mode(write|freeze), offset, before, pattern.
- 주소는 절대값으로 쓰지 않는다: offset = 주소 − 프로그램 로드 기준(PSP 세그먼트×16), pattern = 값 앞 8바이트 + 값 자리(??) + 뒤 8바이트의 16진.
- 적용할 때: 기준+offset 에서 무늬가 맞으면 그 위치, 안 맞으면 RAM 전체를 무늬로 훑어 가장 가까운 일치, 하나도 없으면 「위치 못 찾음」을 보이고 쓰지 않는다.
- 파일을 지우거나 없어도 게임 동작에 영향 없음.

### 구현 위치
- 호스트: `src/app/kh_cheat.h`(검색·쓰기·고정·저장·재배치), 고정 값은 `RENDER_EndUpdate()` 의 `kc::tick()` 이 에뮬 프레임마다 다시 쓴다.
- UI: `src/ui/screens/cheat.h`(S_CHEAT), 호출구 `Env::cheat`(ui_env.h 에서 `gh_cheat_op` 연결).
- 문구: ko/en/ja 세 언어, 영문 키(`ch_*`, `pg_cheat`).

## 2단계 (설계만) — 작품별 이름 있는 치트
- 같은 JSON 에 `named` 구역: 「돈」「HP」 같은 이름 + 작품·빌드 sha 별 후보 주소/무늬. 환세 4작(kaitou·kitan·torimono·hukyou)은 이전 디컴파일 분석에서 나온 주소 후보를 이 표에 먼저 넣고, 1단계 재배치 무늬 방식으로 검증한 것만 「확인됨」 표시.
- 화면: 치트 메뉴 첫 줄에 작품 이름 치트 목록(값 입력 → 쓰기/고정). 이름 없는 작품은 1단계 화면만.
- 환세 4작 주소 후보 표는 분석 산출물에서 옮겨 채운다(지금 이 문서에는 미기재 — 근거 없이 쓰지 않음).

## 3단계 (설계만) — 헥스 뷰어·세이브 편집
- 헥스 뷰어: RAM 0~9FFFF 를 16바이트 줄로 보여주고 패드 이동·값 편집(읽기 전용 기본, 쓰기는 1단계와 같은 자동 슬롯 선저장).
- 세이브 편집: 사용자 세이브가 아니라 「복사 디스크」(작업 사본)에만 허용. 원본·사용자 세이브 직접 편집 금지. 편집 전 사본 백업 한 벌.

## 위험·미검증
- 이번 커밋은 빌드·실행 전(정적 검토만). 컴파일·화면·찾기→고정 동작은 「빌드 ㄱ」 이후 확인.
- 로드 기준(PSP)은 DOS 프로그램이 바뀌면(예: 마도물어 디스크 교체) 달라진다 → 무늬 재탐색이 보완.
